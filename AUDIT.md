# Проверки качества и воспроизводимости

[← О проекте](README.md) · [Методология](docs/methodology.md) · [Результаты](docs/results.md)

Этот документ фиксирует проверенные свойства реализации и открытые вопросы эксперимента.

## Автоматические проверки

Команда: `python -m unittest discover -s tests`.

| Проверка | Что проверяет |
|---|---|
| Метрики | Известные ранжирования, точные ничьи, недопустимые score, отсутствие положительных пользователей |
| Парный bootstrap | Постоянная пользовательская разность сохраняется во всех повторных выборках |
| Генерация признаков | Общие признаки ручного и автоматического кода совпадают на синтетическом примере |
| Cutoff | Событие ровно на границе не попадает в историю; пустая история лайков допустима |
| Горизонт метки | Исключение последнего часа кандидатного окна и соответствующее поведение обоих train builders |

Четыре тестовых метода объединяют эти сценарии. Дополнительно выполнен smoke-test Optuna: один trial на синтетических данных с сохранением истории в CSV.

## Проверка контрольной серии

Для трёх частей подтверждены равенство `uid/item_id/label`, порядка строк ручного/автоматического наборов и нулевой `ui_likes_all` после фильтра. На test 1 333 420 строк, 4941 пользователь, 1656 пользователей с позитивами.

Повторно обучены четыре классификатора. Выполнен bootstrap на 2000 повторов. Опубликованы метрики, параметры, важности и версии; входные parquet идентифицированы SHA-256. Последовательный ноутбук сохраняет результаты из предсказаний, без ручного ввода метрик.

## Принятые решения

- Метрики сначала вычисляются по пользователям; bootstrap пересэмплирует парные разности. Это исключает повторную случайную перестановку ничьих внутри bootstrap.
- Точные ничьи разрешаются стабильным порядком строк. Неравные score не модифицируются.
- Point delta, bootstrap mean и доверительный интервал сохраняются раздельно.
- Параметры и варианты выбираются по val. Исторические и контрольные результаты хранятся раздельно.
- Генераторы train и отдельный скрипт пересборки учитывают часовой горизонт метки. Пустая история не вызывает ложного падения проверки cutoff.

## Открытые вопросы

1. **Временной протокол.** Контрольные метрики рассчитаны на прежних таблицах без явного timestamp/cutoff. Пересборка с часовым зазором реализована, но полный прогон не выполнен. Полнота likes до конца listens требует проверки.
2. **Исторический Optuna.** Сохранены best_params и метрики, но не trials, бюджет, seed и окружение. Новый полный поиск с одинаковым бюджетом ещё не проведён.
3. **Независимость оценки.** Test использовался при исследовании; нужен новый временной период. Один seed пользователей не показывает устойчивость на других подвыборках.
4. **Область задачи.** Оцениваются прослушивания, включая повторы, а не рекомендации уникальных треков из каталога. Доступность is_organic для будущего кандидата отдельно не подтверждена.
5. **Ранкер.** Для нового эксперимента нужно явно сохранять `(cutoff, uid)`; исторический snapshot_id отсутствует.
6. **Интерпретация.** Незначимая разность не доказывает эквивалентность; gain не является причинной оценкой. В раннем bootstrap auto-pruned уступает расширенной ручной модели, поэтому нельзя считать все сравнения незначимыми.

Исторический ноутбук и старые отчёты сохранены для трассировки исследования. Они могут содержать промежуточные выводы и не заменяют актуальную методологию.
