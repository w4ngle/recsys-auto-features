# Автоматизация генерации признаков в рекомендательных системах

Исследовательский проект на Yambda-50M: сравнение ручных признаков LightGBM и шаблонной
автогенерации `сущность × событие × окно`. Итоговая проверка: 31 октября 2026.

**Вывод:** автоматический набор конкурентоспособен по точечным метрикам, но его статистически
подтверждённое превосходство не показано. Нельзя делать вывод «не хуже» без отдельной проверки
non-inferiority. Повторный запуск на существующих кешах выполнен; пересборка с исправленными
временными границами и полный новый поиск Optuna остаются отдельными этапами.

## Данные и постановка

Строка — прослушивание, метка — первый лайк пары uid/item в течение часа после него.
Использованы 5000 выбранных пользователей (`seed=42`) со всей историей. Train — четыре
недельных среза; val и test — следующие 14-дневные интервалы. История признаков строго до cutoff.
Пары, уже лайкнутые до cutoff, исключены. Повторные прослушивания одной пары не дедуплицируются.
Это ранжирование наблюдённых событий, а не уникальных треков всего каталога.

| Часть | Строк | Пользователей после фильтров | Пользователей с позитивом |
|---|---:|---:|---:|
| train | 2349940 | 4424 | 2047 |
| val | 1309444 | 4371 | 1623 |
| test | 1333420 | 4941 | 1656 |

NDCG@10 и Recall@10 усредняются **только по пользователям с позитивом**. Ручные и автоматические
таблицы проверены на совпадение uid/item_id/label и порядка строк во всех частях.

## Признаки

- Ручные: 37 (`u`, `i`, `ui`), 61 с `uar`/`ual`; окна 1, 7, 30 дней и all-time.
- Автоматические: 151 после исключения констант `ui_likes_*` и `ui_cr_*`; окна 1, 3, 7, 14,
  21, 30, 60, 90, 180 дней и all-time. Счётчики, конверсии и средняя доля прослушивания.
- Архивные эксперименты включают top-37, корреляционный отсев и LambdaRank.
  В итоговом проверочном прогоне они не переобучались.

Большой gain длинных окон — наблюдение о модели, а не доказательство их причинного влияния.
Ручной набор тоже содержит all-time историю.

## Результаты: повторный прогон на существующих кешах

| Классификатор | Признаков | NDCG@10 val | NDCG@10 test | Recall@10 test |
|---|---:|---:|---:|---:|
| default manual+ar/al | 61 | 0,083245 | 0,097539 | 0,124424 |
| сохранённые Optuna params: manual+ar/al | 61 | 0,094114 | 0,095070 | 0,125752 |
| default auto-all | 151 | 0,085212 | 0,091007 | 0,119185 |
| сохранённые Optuna params: auto-all | 151 | 0,089725 | 0,097770 | 0,123910 |

Сохранённые Optuna параметры повторно применены, новый полный поиск не запускался.
Ручная настроенная модель выбрана по val; test не используется для выбора.
Точечная разность настроенной автоматической и настроенной ручной моделей: **+0,002700**
(примерно +2,84% относительно ручной). Парный bootstrap по 1656 пользователям test с позитивом:
2000 повторов, seed=42, среднее +0,002617, 95% CI **[−0,004240; +0,009805]**.
Интервал включает ноль. Это не доказательство эквивалентности.

Точные числа, модели, важности и версии: `reports/recheck/`. Окружение проверочного запуска:
Python 3.14.0, LightGBM 4.7.0; полные версии — `run_metadata.json` и `requirements-checked.txt`.
Разрешение точных ничьих в ранжировании теперь стабильно по порядку строк, без jitter.

## Исторические результаты и Optuna

| Классификатор | NDCG@10 val | NDCG@10 test | Recall@10 test |
|---|---:|---:|---:|
| default manual+ar/al | 0,0777 | 0,0852 | 0,1136 |
| default auto-all | 0,0812 | 0,0848 | 0,1151 |
| Optuna manual+ar/al | 0,0837 | 0,0883 | 0,1181 |
| Optuna auto-all | 0,0820 | 0,0909 | 0,1186 |

Эти числа взяты из исходного `optuna_results.json`, а не из нового запуска. Историческое
преимущество auto на test +0,0026 (около +2,94%). JSON содержит bootstrap mean +0,001726
и CI [−0,002900; +0,007123]; mean не равен разности округлённых метрик и не должен так называться.
Без исходных предсказаний расхождение проверить нельзя.

Optuna запускался, однако число trials, seed, версии, пространство и журнал исторического
поиска не сохранены. Равенство бюджетов не подтверждено. В `src/tuning.py` добавлен **новый**
протокол: по 30 trials для каждого набора, TPE seed=42, одинаковое пространство, цель NDCG@10
на val, SQLite и CSV trials. Early stopping классификатора — по binary logloss на val.
Документация: [Optuna RDB storage](https://optuna.readthedocs.io/en/stable/tutorial/20_recipes/001_rdb.html),
[reproducibility](https://optuna.readthedocs.io/en/stable/faq.html).

## Найденные ограничения протокола

**Горизонт метки:** исходные кеши не учитывают часовой зазор у границ выборок и конца
наблюдений. Метка последнего часа train может использовать события из val; в конце test
возможны незавершённые метки. Timestamp/cutoff в кешах отсутствуют, поэтому повторный прогон
не доказывает отсутствие временной утечки. Исправление реализовано для пересборки:
train builders исключают последний час недельных окон, `prepare_data.py` — также val/test.
Новые таблицы сохраняются в `data/rebuilt/`, старые не перезаписываются.
Полноту likes до конца listens необходимо подтвердить на исходной выгрузке.

Один seed пользователей; test просматривался многократно; исторический поиск не воспроизводится
по одному best_params; для LambdaRank не сохранён явный snapshot_id; доступность is_organic
для реального будущего кандидата не подтверждена. Полный разбор и проверки: `AUDIT.md`.

## Запуск

Из корня проекта:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# macOS при необходимости: brew install libomp
python -m unittest discover -s tests
```

Поместить шесть прежних `Xtr/Xva/Xte[_a]_5k.parquet` в `data/` либо указать их папку через
`RECSYS_DATA_DIR`. Открыть `notebooks/T-Lab.ipynb`, выполнить Restart Kernel and Run All.
Выполненные ячейки в поставке используют старые кеши и RUN_SEARCH=False.

Для исправленного временного протокола:

```bash
python prepare_data.py
export RECSYS_DATA_DIR="$PWD/data/rebuilt"
```

После этого перезапустить ноутбук. Для нового поиска: `RUN_SEARCH=True`, по 30 trials,
уникальный `STUDY_TAG`. Новый run перезаписывает `reports/recheck/`; перед повторным запуском
сохранить предыдущий прогон при необходимости. Исторические артефакты остаются неизменны.
Крупные данные и модели исключены из Git; модели включены в итоговый ZIP.
