## 1. Окружение

Контрольный запуск выполнен на Python 3.14.0. Версии основных пакетов сохранены в [requirements-checked.txt](../requirements-checked.txt), полные метаданные запуска — в [run_metadata.json](../reports/recheck/run_metadata.json). Совместимость с другими версиями Python отдельно не проверялась; файл версий не является полным lockfile всех транзитивных зависимостей.

```bash
git clone https://github.com/w4ngle/recsys-auto-features.git
cd recsys-auto-features
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-checked.txt
python -m unittest discover -s tests
```

На Windows активация окружения: `.venv\Scripts\activate`. На macOS при отсутствии OpenMP: `brew install libomp`. Для просмотра и запуска ноутбука можно использовать редактор с поддержкой Jupyter и выбрать Python из `.venv`. Пакет `ipykernel` включён в зависимости; сам интерфейс Jupyter не поставляется проектом.

Тесты не требуют исходного датасета: проверяют NDCG/Recall, bootstrap, соответствие общих признаков и временные границы на небольших примерах.

## 3. Повторное обучение на сохранённых таблицах

Этот режим повторяет контрольный эксперимент на прежнем временном протоколе. Для него нужны шесть ранее подготовленных файлов:

```text
data/
  Xtr_5k.parquet
  Xva_5k.parquet
  Xte_5k.parquet
  Xtr_a_5k.parquet
  Xva_a_5k.parquet
  Xte_a_5k.parquet
```

Либо укажите другую папку:

```bash
export RECSYS_DATA_DIR="/path/to/prepared-tables"
```

Откройте `notebooks/T-Lab.ipynb` из корня проекта или папки `notebooks/`. Выберите окружение `.venv`, оставьте `RUN_SEARCH=False` и выполните Restart Kernel → Run All.

Ноутбук проверяет совпадение `uid/item_id/label` и порядка строк ручного и автоматического наборов. Затем обучает четыре модели и сохраняет метрики, важности, модели, параметры и bootstrap в `reports/recheck/`.

**Повторный запуск перезаписывает файлы этого каталога.** Если нужно сохранить опубликованную серию, предварительно скопируйте `reports/recheck/` в отдельную папку. SHA-256 таблиц контрольного запуска находятся в [input_manifest.json](../reports/recheck/input_manifest.json). Ноутбук не обновляет этот manifest автоматически: для новых таблиц нужно записать новые контрольные суммы отдельно.

## 4. Пересборка из Yambda с часовым зазором

Если сохранённых таблиц нет или нужно проверить исправленный временной протокол:

```bash
python prepare_data.py
export RECSYS_DATA_DIR="$PWD/data/rebuilt"
```

Скрипт загружает listens, likes и маппинги из Hugging Face, выбирает пользователей и рассчитывает ручные/автоматические таблицы. Для загрузки требуется доступ к сети. После первого скачивания библиотека может использовать локальный кеш.

В памяти обрабатываются исходные события и таблицы признаков; подготовка существенно тяжелее тестов. Точное минимальное потребление памяти и время выполнения не измерены. Файлы сохраняются в `data/rebuilt/`, прежние таблицы в `data/` не изменяются.

Пересборка исключает последний час каждого train-окна, val и test, оставляя время для формирования метки. Полноту лайков до конца наблюдений прослушиваний необходимо подтвердить на исходных данных. После подготовки нужно выполнить ноутбук заново и отдельно задокументировать новую серию.

**Этот полный режим пока не выполнен.** Опубликованные таблицы метрик не относятся к пересобранным данным.

## 5. Новый поиск Optuna

В ноутбуке:

```python
RUN_SEARCH = True
N_TRIALS = 30
```

В ячейке поиска задайте уникальный `STUDY_TAG`, например `gap-v1-30trials-seed42`. Значение не должно совпадать с уже существующей study в SQLite. Намеренное отсутствие `load_if_exists=True` защищает от случайного продолжения другой серии.

Оба набора получают одинаковое число trials и пространство. Оптимизируется NDCG@10 на val; early stopping модели использует logloss на val. Test не передаётся в функцию подбора.

Сохраняются `optuna.sqlite3`, CSV trials и лучшие параметры. SQLite и файлы моделей игнорируются Git. Полный новый поиск не запускался; работоспособность модуля проверена одним trial на синтетических данных.

## 6. Как сравнивать серии

Фиксируйте происхождение таблиц, версии окружения, seed, параметры и число trials. Не объединяйте исторические и новые числа в одну серию. Для окончательного вывода нужен новый временной test и проверка на нескольких seed пользователей.
